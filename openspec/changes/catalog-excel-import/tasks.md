# Tasks: Internal Catalog Bulk Import from Excel (F2)

> Strict TDD. Inside every phase: RED task (test written, fails for the stated reason) -> GREEN task -> REFACTOR only when named. Where a task is a characterization pin that cannot be RED, it says so.
> Spec abbreviations: AC = `academic-catalog`, CEI = `catalog-excel-import`, IAP = `imported-account-provisioning`, FPC = `forced-password-change`, AL = `audit-log`. Design decisions are cited as D1-D26, findings as F1-F7, cross-checks as X1-X9.
> Tags: **[READ-ONLY]** allowed without confirmation (project CLAUDE.md); **[CONFIRM]** touches or may touch a database, or generates migration files, and needs the user's explicit "yes" **for that exact command**; **[GATE]** blocks the tasks named after it; **[USER]** needs input only the user can give.
> **`drizzle-kit push` is FORBIDDEN in every phase** (F7: it would propose dropping the child partitions). Never run `db:migrate`, `db:seed`, `neon` writes or write SQL without a per-command "yes". A confirmation for one command never covers the next one.
> Tests never import `@/db` (except the schema-only files) or `@/env`: pure modules, `vi.mock("server-only", () => ({}))` (F5), `toSQL()` via `new QueryBuilder()` from `drizzle-orm/pg-core`, hand-rolled `tx` doubles. Lint check everywhere: `npx eslint src | rg -v 'Delete .␍.'` shows no real errors (CRLF noise is pre-existing). Before touching any Next.js API (`next.config.ts`, route handlers, `maxDuration`) read the matching guide in `node_modules/next/dist/docs/` (AGENTS.md).
> Branch/PR actions are performed by the user (`roles-lookup-table` precedent). The `sdd-tasks` 530-word cap is knowingly exceeded: eight slices with full spec traceability need the room.
