# Proposal: Validation Signals

## Intent

The secretary decides requests without automated warnings about late
presentation, incoherent or uncovered dates, issuer recurrence or reused
documents. Deliver roadmap row 5 partially: RF-05 (a)-(d); RN-07, RN-09,
RN-10, RN-14, RN-15, new RN-26; touches RNF-01. Pre-proposal handoff
revision 2 is authoritative; evidence in `exploration.md`.

## Scope

### In Scope
- **S1** Each signal: `present | absent | not_evaluable` (closed reason code).
- **V1** Suggested verdict: "review carefully" (any present), "no alerts"
  (none present, all evaluable), "inconclusive" (otherwise); not-evaluable
  signals listed apart. Display-only (RN-15): no write path reads it, tested.
- **X2** RN-07 via `deadlineOf(fechaFin)` vs first `presentadaEn`.
- **R10** RN-09; RN-10 full containment of `[fechaInicio, fechaFin]`.
- **X3** RN-14 issuer normalized in TypeScript; threshold constant (3) passed
  as params; period from `Grupo.periodo`.
- **R26/X1** RN-26 repeated document: SHA-256 stored at finalize; earlier-only
  match against other presented requests; other id only inside caller scope.
- **SNAP/X4** Computed on read; secretary `SignalsSection`; coordination
  read-only projection; students see nothing; queue untouched.
- Add RN-26 to `docs/requirements.md` (+ changelog row); update roadmap row 5.

### Out of Scope
- RF-05 (e), RN-11, RN-12, RN-13, RN-24: deferred to RF-14.
- NS-12; cross-student issuer volume; decision-time snapshot; fingerprint
  backfill (old documents stay NULL, never match); `CONSENT_VERSION` change.

### Known limitations
- **RNF-14 not met**: threshold is a code constant until roadmap #8.
- **Exact-hash**: re-saved, re-compressed or screenshotted files evade RN-26.
- **Extraction dependency**: RN-09/10/14 are not evaluable without
  `completada` extraction rows. The 2026-11-03 system tests need seeded
  extraction rows or the model server; only RN-07 and RN-26 work without it.
- **Privacy**: hashing and cross-request comparison pending UAM legal review;
  validation runs on fictitious data.

## Capabilities

### New Capabilities
- `validation-signals`: signal outcomes, reason codes, verdict, RN-26 matching.

### Modified Capabilities
- `request-review`: signals and verdict on the secretary detail.
- `supporting-documents`: finalize computes and stores the SHA-256.
- `coordination-escalation`: coordinator read-only outcomes; confidentiality.
- `student-requests`: students never see signals.

## Approach

Pure evaluators plus two read queries (RN-14 history, RN-26 hash lookup);
single-stream `DocumentStore` extension feeds signature check and hash.
Strict TDD. Feature-branch chain on `feat/validation-signals`.

| Slice | Content | ~Lines |
|---|---|---|
| S1 | Evaluators, read assembly, secretary UI (RN-07/09/10/14), no schema | 900 |
| S2 | Fingerprint at finalize, migration 0013, RN-26 | 650 |
| S3 | Coordination view, specs/docs closeout | 400 |

S1 lands first (before system tests).

the owner's explicit yes for that command.

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Verdict mostly "inconclusive" without extraction | High | Seed extraction rows; list not-evaluable apart |
| RN-26 leaks cross-scope ids (RNF-01) | Med | Scope-filtered reference; scope tests |
| 0013 collides with another change | Low | Regenerate if another lands first |
| Legal review rejects hashing | Med | S2 separable; revert drops column |

## Rollback Plan

Revert the chain in reverse (S3, S2, S1 independent of schema). If 0013 was
applied, a confirmed down-migration drops the index, check and column; no
other data depends on it. No state changes to undo (display-only).

## Dependencies

- Owner confirmation for migration 0013; UAM legal review before production.

## Success Criteria

- [ ] Each signal yields present/absent/not-evaluable with reason codes.
- [ ] Verdict never changes state (test).
- [ ] Correction re-upload never triggers RN-26; earlier request unaffected.
- [ ] Coordinator sees outcomes only; students see nothing.
- [ ] RN-26 in `docs/requirements.md`.
