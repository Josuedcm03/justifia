Nothing here connects to Neon on purpose; the only commands are tests, typecheck, lint, build, a local `npm start` for HTTP redirect checks, and read-only `rg`/`git`. If a task seems to need one, stop and ask.

## How to read this file

- **Shape.** Seven phases. Phases 1 to 5 are the design's seams A to E, in the design's order (A, B, C before D; E last). Phase 0 is preflight, Phase 6 is guardrails and verification. Executor tasks are plain; **[OWNER]** tasks are the few only the owner can do.
- **One pull request, planned as seven commits** (owner-approved `size:exception`, see the forecast). The owner commits; no executor task stages, commits, pushes or opens a PR. Each phase header lists its commit(s) and which tasks they hold, so the reviewer can read commit by commit. Every commit leaves `npm test` and `npm run typecheck` green.
- **TDD.** Inside a phase: RED (write the test, run it, record why it fails) then GREEN (make it pass) then refactor. A task marked *characterization* pins behaviour that already exists, so it cannot be RED; it says how it is proven (a mutation: break the code, see it fail, restore).
- **Paths.** `CAT` = `src/app/(dashboard)/catalog`. All other paths are repo-relative. Quote paths containing `(dashboard)` or `[id]` in the shell.
- **Moves.** Move files with the filesystem, not git commands; git detects the rename from content. Keep the content close to the old file so the diff reads as a rename.
- **Next.js guide first.** `AGENTS.md` requires reading the guide under `node_modules/next/dist/docs/` before routing, redirect or revalidation code. Task 0.1 does it once; tasks 2.x, 3.x and 4.x depend on it.
- **I18N (paired work).** Every key added, moved, reworded or removed is edited in `i18n/es.json` and `i18n/en.json` in the same task, followed by `npx vitest run src/i18n/catalog-parity.test.ts`.
- **STRUCT (CRLF).** New source-text pins normalise line endings with `.replace(/\r\n/g, "\n")` before matching, like `src/lib/data/catalog-structure.test.ts`. Path-only pins do not need it.
- **FT (flaky-test hygiene).** Every component or page test: await async UI (`findBy*`, `waitFor`); no synchronous query after an interaction; render with the real `es`/`en` catalogs through `NextIntlClientProvider` with an `onError` that throws; resolve action promises inside `act`; no wall clock. Tests never import `@/db` or `@/env`: `vi.mock("server-only", () => ({}))`, `toSQL()` rendering and recording doubles as the existing tests do.
- **V (verify), run at the end of every commit.** (1) the focused test files of the commit with `npx vitest run <files>`; (2) `npm test`; (3) `npm run typecheck`; (4) lint on the touched files in the Windows-safe form `npx eslint <files> | rg -v "Delete .␍."`, where the output must show no remaining `\berror\b` line (`... | rg "\berror\b"` prints nothing); (5) `npm run build` when a route or `next.config.ts` changed (Phases 2, 3, 4). Before a build, confirm no `next dev` is running (it shares `.next`); if one is, ask the owner to stop it, never kill it.
- **Record.** Each executor batch appends what it did, the RED reason, the V results and any deviation to the apply-progress note.
- **Unconfirmed assumptions** are named in the task that depends on them (U1 to U7, U9 to U12 and the spec defaults A-*), so a change of mind shows what to redo.
