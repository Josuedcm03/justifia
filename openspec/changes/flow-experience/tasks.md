## Conventions

> Notation: the token <Q> stands for one double quote character inside SQL identifiers (written out so tooling does not read the SQL as file paths). The token <BS> stands for one backslash. Branch names, commands, URLs, SQL, placeholders and string values such as "otro" are written in double quotes, never in backticks; only real repository file paths are backticked (a file the task creates is a repository path). Thesis workspace paths are written in double quotes with <BS>.
> Test command: T(<filters>) is the command "$env:DATABASE_URL='postgres://u:p@127.0.0.1:9/x'; npm test -- <filters>". Each filter is a substring of a test path. Unit runs never touch a database. No "npm run build" except where a task says "next build".
> Strict TDD (vitest): a behavior-changing task is a RED task (failing test, run and confirm the failure) followed by its GREEN task. A test that passes at write time (it pins existing or already-built behavior) says so and carries a revert-only mutation check: a temporary edit that must make it fail, undone with "git restore <file>", with "git status" confirmed clean of it before every commit. Record every check in `openspec/changes/flow-experience/apply-progress.md`. Vitest does not typecheck, so "npm run typecheck" is its own gate.
> Gates per unit (G): the focused T(...) run, "npm run typecheck", "npx eslint <touched files>", "npx prettier --check <touched files>"; when i18n changed, also T(src/i18n). If CRLF noise appears, filter eslint with "| rg -v 'Delete .␍.'" and run prettier with "--end-of-line auto" (precedent). The full "npm test", "npm run typecheck" and "npx eslint src" run once per PR (second to last task of each PR phase).
> DB rule (`CLAUDE.md`): apply never runs "drizzle-kit migrate", "drizzle-kit push", "db:seed", "db:migrate", "neon" write commands or SQL writes on its own. Every database task is tagged [ASK OWNER]; a write is also tagged [CONFIRM] and needs the owner's explicit "yes" for that exact command, never batched. The owner runs them; apply only records the result. Read-only queries are tagged [READ-ONLY]. "drizzle-kit generate" (task 8.5) reads the schema and writes files; it opens no database connection. Integration and system captures use disposable Neon branches only ("flow-it", a child of "dev-arnia"); never "validacion-secretaria" or "validacion-estudiantes".
