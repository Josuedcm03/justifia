# Tasks: Auth Route Tests

Notation: `<BS>` stands for one backslash character in test inputs (written out so tooling does not read the inputs as file paths).

> Strict TDD (vitest): a task that changes behavior is a RED task (failing test) followed by its GREEN task. Characterization tests (register page and actions, profile page, login page cases that already hold) and the denial matrix pass at write time, because they pin existing behavior; each says so, and each is paired with a mutation check that proves it can fail. Focused command: `npm test -- <paths>` (`vitest run`). Vitest does not typecheck, so `npm run typecheck` is its own gate.
> Gates per unit: focused `npm test`, `npm run typecheck`, `npx eslint <touched files>`, `npx prettier --check <touched files>`. The full `npm test` runs once, at the end (task 4.13). If CRLF noise appears, filter eslint with `| rg -v 'Delete .␍.'` and run prettier with `--end-of-line auto` (precedent).
> DB rule (`CLAUDE.md`): nothing in this change touches a database. Every `npm test` runs with a dummy `DATABASE_URL` (`$env:DATABASE_URL='postgres://u:p@127.0.0.1:9/x'`). No task runs `drizzle-kit`, `db:seed`, `neon`, `npm run dev` against Neon or SQL. There is no `[ASK OWNER]` database task here; the `[ASK OWNER]` markers below are decisions and the merge.
> Spec IDs: AEA-1..AEA-4 (`specs/auth-entry-access`), RAC-1..RAC-7 (`specs/route-access-coverage`). Every task covers RNF-01 (c). Decisions D1..D12 refer to `design.md`.
> Skills for apply: `work-unit-commits`, `chained-pr` (registry `.atl/skill-registry.md`). One commit per work unit (tests and code together), Conventional Commits, no AI attribution, no `Co-Authored-By`.
> Never stage: `FORMATO SOLICTUD DE JUSTIFICACION DE AUSENCIA.docx`, `constancias_ficticias/`, `infra/modal/__pycache__/`, `.engram/`, `package-lock.json`. Mutation checks are temporary edits: revert them with `git restore <file>` and confirm `git status` is clean of them before every commit.
> Edit authority: a backticked path on a checkbox line is an edit target; read-only references carry `(read-only)`.
> Threat matrix: N/A (design). The redirect-target boundary is covered by the rejected values in task 1.2.
> Size note: the `sdd-tasks` cap (530 words) is exceeded on purpose; the repository precedent keeps one line per task with spec links.
