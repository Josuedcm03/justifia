# Tasks: Manual Catalog Management (Catálogos)

> Strict TDD. Inside every phase: RED task (test written, run, fails for the stated reason) -> GREEN task -> REFACTOR only when named. A task labelled "characterization pin" cannot be RED; it says how it was proven (mutation check).
> Spec abbreviations. `catalog-management`: CM-ACC, CM-SCOPE, CM-ASG, CM-GRP, CM-LST, CM-UX, CM-NAV, CM-I18N, CM-NFR, CM-AUD (ids as written in the spec). `academic-catalog` delta: AC-LIFE (Asignatura lifecycle), AC-CODE (Codigo immutable), AC-ORIG (Grupo origin marker), AC-PAR (manual writes need active parents), AC-ADD (additive schema), AC-READ (active-only reads), AC-ASG (Asignatura shape), AC-GRP (Grupo shape/period). `audit-log` delta: AL-SET (closed set of events), AL-ONE (one row, same transaction), AL-PAY (field names only), AL-IMP (import audit). `catalog-excel-import` delta: CEI-PREC (precedence), CEI-PREV (preview figures), CEI-COPY, CEI-BUSY, CEI-VAL (row validation), CEI-DRY (dry run), CEI-UPS (upserts), CEI-DEA (deactivate absent), CEI-AUD (import-level audit). Design decisions: D1-D13; findings N1-N9, R1-R12; gates G1-G10; amendments introduced here: A-1..A-8 (table below).
> Tags: **[READ-ONLY]** allowed without confirmation (project CLAUDE.md); **[CONFIRM]** touches or may touch a database, a Neon branch, or generates migration files: needs the user's explicit "yes" **for that exact command**; **[GATE]** blocks the tasks named after it; **[USER]** needs input or an action only the user can give or perform.
> **`drizzle-kit push` is FORBIDDEN in every phase.** Never run `db:migrate`, `db:seed`, `neon` writes or any write SQL without a per-command "yes"; a "yes" for one command never covers the next. **Agents never commit, push or create branches**: every branch, commit and PR step is a [USER] task.
> **HC (host check), applies to every [CONFIRM] task that writes to a Neon branch (1.15-1.26, 1.29-1.31):** before the command, restate the host part of the connection string in use (never credentials), compare it with the shared host recorded in 1.2, and abort if they are equal when the target is a rehearsal branch, or different when the target is `production`.
> **FT (flaky-test hygiene), applies to every component and page test task:** await async UI (`findBy*`, `waitFor`); no synchronous query after an interaction; `fireEvent.change` for inputs `user-event` would filter (number inputs, `accept`); render with the real `es` and `en` catalogs through `NextIntlClientProvider` with an `onError` that throws; resolve every action promise a test starts inside `act` before the test ends (apply-progress finding 3, `catalog-excel-import`); never read popup contents synchronously.
> **Known flaky set (pre-existing, recorded in every batch of `catalog-excel-import`):** `denied/page.test.tsx` (2 tests), `users/page.test.tsx` (2), `data-table-search.test.tsx` (1). Phase 0 records the exact names; "green" in this document means "no failure outside that set".
> **V (unit verification) = focused command of the unit, `npm test`, `npm run typecheck`, `npx eslint <touched files> | rg -v 'Delete .␍.'` (CRLF noise is pre-existing), and `npm run build` when a route or config changed.**
> Tests never import `@/db` (except schema-only files) or `@/env`: `vi.mock("server-only", () => ({}))`, `toSQL()` through `new QueryBuilder()` from `drizzle-orm/pg-core`, hand-rolled recording `tx` doubles. Before writing any Next.js code re-read the matching guide in `node_modules/next/dist/docs/` (AGENTS.md); the design's N1-N9 are the starting point, not a substitute.
> The `sdd-tasks` 530-word cap is knowingly exceeded: fourteen units with full spec traceability need the room (precedent: `catalog-excel-import/tasks.md`).
