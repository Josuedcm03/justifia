### Lessons from this session, encoded in the tasks below

1. **Executors have no memory tool.** Every batch ends by appending a dated section to `apply-progress.md` (tasks done, RED evidence, V results, authored lines by path, deviations, new locale keys). The orchestrator saves Engram from that file. A task is not done until its batch note exists.
2. **Nothing is committed, so every piece is measured by path as a delta over a recorded baseline:** `git diff --numstat` for tracked files and a line count (`rg -c "" <file>`) for untracked ones, both read from the main shell at the start of the piece (baseline tasks 16.4, 17.2, 18.1 and the first read task of Phases 10, 12 and 13). The measure of a piece is the sum of the deltas of the paths it names. Measure after each GREEN and stop at the seam when the sum passes 800.
3. **Copy is authored late and small.** A task that needs real locale keys for a component or page test says "author only the keys this test strictly renders, count them, and still show the parity RED first". Executors measured late twice by authoring copy early.
4. **`guards.test.ts` forbids a page importing `*/actions`.** Pages bind actions through a client `bound-controls.tsx` module; the Grupo pages follow the Asignatura pattern (`grupos/bound-controls.tsx`, task 13.7).
5. **A dev server may be running** (`next dev` on port 3100 against `rehearsal-catalog-ui`, which lacks `0006`). Any task that runs `npm run build` first checks that (both use `.next`); if one is running, ask the owner to stop it, never kill it. The same server must not run an import apply between 16.14 and DG9 (16.34).
6. **Shell limits:** `sd` is not installed; `rg` is not available inside child shell scripts (use it only from the main shell or use the dedicated tools); never `cat`, `grep`, `find`, `sed`, `awk`, `ls`.
7. **Standing owner preference:** split at a documented seam instead of `size:exception`; each new piece is planned under 800 authored lines with the 1.3x-2x overshoot of this change in mind.
8. **Nothing here instructs an agent to commit, push, branch or run a database write.** Every branch, commit and PR step is [USER]; every database write is a per-command [CONFIRM] with HC.
